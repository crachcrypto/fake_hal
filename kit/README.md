# FakeHAL — комплект для бота (что за что отвечает)

Папка на VPS: `/root/fakehal_bot_kit/`
Задача комплекта: чтобы бот при покупке отдавал клиенту НЕ только APK, а всю начинку —
и «Start failed» из-за отсутствия файлов больше не повторялся.

## Почему это нужно
«Start failed» у клиента был потому, что он поставил только 2 APK (FakeControl + SpoofKit Xposed)
и дал root, но сама начинка FakeHAL на телефон не попала (её стёр сброс/ручная переустановка).
Бинарь и библиотеки лежат на телефоне в `/data/local/tmp/` — без них кнопка START не поднимает камеру.

## Состав payload/ (кладётся на телефон в /data/local/tmp/)
- `fake_camera_provider` — скомпилированный бинарь HAL (ARM64). Это и есть «камера». Исходников тут НЕТ.
- `afbc_encoder.so`, `gralloc_uv_fix.so` — библиотеки, грузятся через LD_PRELOAD при старте бинаря.
  Дубли этих .so также кладутся в `/data/adb/modules/FakeHAL/` (бинарь под setsid ищет их по пути модуля).
- `fakehal.conf` — конфиг стрима (какая камера активна, ориентация, шум и т.п.).
- `fake_camera_hal.xml` — манифест провайдера.
- `fake_video.mp4` / `fake_video_front.mp4` — подставные ролики (задняя/фронтальная).
- `fakehal_gate.sh` — лицензионный гейт + вотчдог (см. ниже).
- `DEPLOY.sh` — автодеплой: раскладывает всё по путям, ставит права/SELinux-контексты, создаёт module.prop.

## verify_server.py (остаётся на VPS, НЕ на телефоне)
- HTTP-сервер проверки ключа. Слушает `0.0.0.0:8787`.
- `GET /verify?key=FH-...&device=SERIAL` → `{"valid":bool,"reason":"ok|expired|inactive|unknown_key|no_key|device_limit","remaining_sec":N,"expires_at":"..."}`.
- Читает тот же `keys.json`, что и бот (только чтение). Работает как systemd-юнит `fakehal-verify.service` (автозапуск+рестарт).

## Как работает блокировка по ключу (gate)
1. Ключ клиента пишется в `/data/local/tmp/fakehal_key`.
2. START вызывает `sh /data/local/tmp/fakehal_gate.sh once`:
   - ключ валиден → HAL запускается;
   - ключ истёк / неактивен / неизвестен → HAL убивается и не стартует.
3. Вотчдог `... loop` проверяет каждые 5 мин и глушит стрим по истечении срока.
4. Возврат работы: вписать новый рабочий ключ в `fakehal_key` и вызвать `once` — HAL поднимется сам.

Гейту нужен HTTP-инструмент на телефоне: curl / wget / busybox.
На KernelSU busybox лежит в `/data/adb/ksu/bin/busybox` — скрипт уже умеет его находить по абсолютному пути.

## Проверено на живой трубке (Pixel 7, 5559) 2026-08-04
- Подмена камеры в Open Camera — РАБОТАЕТ (кадры из fake_video.mp4, подтверждено логом + скрином).
- Google Камера — падает (капризна к кастомному HAL, это ожидаемо; целевой клиент — Open Camera и обычные Camera2-приложения).
- Gate: валидный ключ → HAL up; истёк/неактивный/неизвестный → HAL killed+blocked; новый рабочий ключ → HAL снова up. Все 3 сценария зелёные.

## Что НЕ уходит клиенту (только на VPS)
- Исходный C++ код HAL (`/root/fake_hal_aidl/`), скрипты сборки — только компилированные бинарники идут на телефон.
- База ключей `keys.json`, токены бота — только на сервере.
